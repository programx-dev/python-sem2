# Отчет по лабораторной работе №4

**Тема:** Асинхронный исполнитель задач  
**Предметная область:** Платформа обработки задач

## Цель работы

Целью работы является проектирование и реализация системы асинхронной обработки задач с использованием модели управления `asyncio`. Основное внимание уделено освоению конкурентного выполнения кода, реализации паттерна Producer-Consumer через асинхронные очереди, применению асинхронных контекстных менеджеров и обеспечению неблокирующего ввода-вывода при работе с внешними источниками данных.

## Архитектурные решения

В ходе реализации асинхронного движка были применены следующие подходы:

### Асинхронные источники

Источники задач из предыдущих лабораторных были расширены поддержкой протокола `TaskSourceProtocol`. Использование `async for` и метода `get_async_tasks` позволяет извлекать задачи без блокировки основного потока выполнения. Компонент `AsyncInboxTasks` агрегирует асинхронные потоки из разных источников, обеспечивая совместимость для синхронных реализаций из предыдущей лабораторной через принудительную передачу управления event loop с помощью await asyncio.sleep(0).

### Очередь с помощью asyncio.Queue

Реализован класс `AsyncTaskQueue`, выступающий связующим звеном между источниками и исполнителями:

* Ипользование стандартной `asyncio.Queue` гарантирует корректную работу при одновременном доступе нескольких корутин.
* Реализован механизм уведомления потребителей об окончании данных через помещение None в очередь. Это позволяет воркерам корректно завершать свой жизненный цикл после исчерпания источников.

### Асинхронный исполнитель и пул воркеров

Класс `AsyncExecutor` реализует логику параллельной обработки:

* Через `__aenter__` и `__aexit__` осуществляется автоматический запуск фонового наполнения очереди и гарантированная очистка ресурсов.
* Исполнитель запускает заданное количество независимых корутин-воркеров. Они конкурентно извлекают задачи из очереди и передают их на обработку зарегистрированным хендлерам, что позволяет эффективно использовать время ожидания (например при имитации сетевых задержек).

## Особенности реализации

### Неблокирующая работа и обработка ошибок

Система спроектирована таким образом, что операции не блокируют Event Loop. Воркеры снабжены централизованной обработкой исключений: ошибка в одном из обработчиков логируется, но не приводит к остановке всего исполнителя или других воркеров.

### Контракты обработчиков

Использование `typing.Protocol` для `TaskHandlerProtocol` позволило добиться того, что истема исполнения ничего не знает о внутренней логике обработки и может работать с любым объектом, имеющим асинхронный метод `handle(task)`.

## Тестирование и демонстрация работы (версия без Docker)

Пример запуска асинхронного исполнителя с использованием нескольких воркеров и фильтрации:

**Команда запуска:**

```bash
uv run lab4 async-run --gen 15 --workers 3 --min-priority 50 --handler logging --handler email
```

## Инструкции по запуску в Docker

### Сборка образа

Находясь в корневой папке лабораторной работы №4:

```bash
docker build -t lab-04 .
```

### Варианты запуска программы

**Пр. 1: Запуск асинхронной обработки (Генератор + API):**

```bash
docker run --rm lab-04 async-run --gen 20 --api --workers 5 --handler logging
```

**Пр. 2: Асинхронная обработка с фильтрацией по статусу:**

```bash
docker run --rm lab-04 async-run --jsonl ./data/tasks.jsonl --status new --handler email
```

**Пр. 3: Проверка списка доступных обработчиков:**

```bash
docker run --rm lab-04 handlers
```

### Запуск тестов и проверка покрытия

Для проверки корректности асинхронной логики и достижения покрытия >80%:

```bash
docker run --rm --entrypoint pytest lab-04 --cov=src
```

## Вывод

В ходе работы был реализован асинхронный исполнитель задач, использующий конкурентную модель выполнения. Применение `asyncio.Queue` и пула воркеров позволило создать систему, способную масштабировать обработку задач без увеличения количества системных потоков. Продемонстрированы преимущества асинхронного подхода при работе с операциями с вводом-выводом и обеспечена отказоустойчивость системы за счет изоляции ошибок в воркерах.
